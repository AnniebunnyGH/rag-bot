## 1. Введение и бизнес-контекст

### 1.1. О компании QuantumForge Software
**QuantumForge Software** — продуктовая IT-компания (штаб-квартира в Хельсинки, R&D в Таллине), работающая на рынке 9 лет.
- **Флагманский продукт:** SaaS-платформа **«Digital Twin»** (цифровые двойники промышленных объектов). Ключевые клиенты — промышленные гиганты **ABB** (швейцарско-шведская корпорация), **Wärtsilä** (финский производитель энергетического оборудования) и ряд скандинавских энергокомпаний.
- **Консалтинг (~20% оборота):** проектная интеграция цифровых двойников в SCADA-системы заказчиков.

### 1.2. Кто ставит задачу и для кого разрабатывается решение?
- **Стейкхолдеры (кто ставит задачу):**

  - **HR и операционный менеджмент:** сокращение онбординга новых инженеров (новые сотрудники тратят до 4 часов в неделю на поиск информации).
- **Конечные пользователи бота:**
  1. **Инженеры и разработчики:** поиск Architecture Decision Records (ADR), спецификаций REST/gRPC API, схем зависимостей в монорепозитории.

  4. **Менеджеры и аналитики:** бизнес-правила, регламенты, SLA.

1. **Конфиденциальность промышленного уровня:** В базе знаний содержатся сетевые топологии, схемы SCADA, архитектурные особенности объектов энергетики и закрытый код. Утечка таких данных недопустима.

## 2. Сравнительный анализ LLM-моделей

Исследованы три категории моделей: локальные открытые модели (Hugging Face), эталонные облачные модели (OpenAI) и региональные облачные решения (YandexGPT).

| Критерий | Hugging Face (Llama-3.1-8B-Instruct, Mistral-Nemo-12B) | OpenAI API (GPT-4o-mini / GPT-4o) | YandexGPT (Yandex Cloud API) |
| :--- | :--- | :--- | :--- |
| **Качество ответов и галлюцинации** | **Высокое** при качественном RAG-контексте. 8B/12B модели отлично справляются с английским языком и кодом. Модели 70B сопоставимы с GPT-4o, но требуют кластера GPU. | **Эталонное (State-of-the-Art).** Превосходное удержание контекста, идеальное следование инструкциям Few-Shot и Chain-of-Thought (CoT), минимальный уровень галлюцинаций. | **Хорошее** на русскоязычных текстах, однако заметно уступает на сложном техническом английском, монорепозиторном коде и промышленных терминах. |
| **Скорость работы (Latency / TPS)** | **Экстремальная** при наличии локального GPU (vLLM / TensorRT-LLM): 40–90 токенов/сек, Time-to-First-Token (TTFT) < 150–200 мс в локальной сети. | **Высокая и стабильная** через HTTP API: TTFT $\approx$ 300–600 мс, генерация 60–100 токенов/сек. Зависит от внешнего канала. | **Средняя**: генерация 25–45 токенов/сек, сетевая задержка при вызовах из европейского периметра (Финляндия/Эстония). |
| **Стоимость владения (TCO)** | Фиксированная аренда GPU (например, AWS EC2 `g5.xlarge` с NVIDIA A10G 24GB $\approx$ **\$700–900/мес**). Выгодно только при непрерывном потоке миллионов запросов. | Оплата за фактически потребленные токены. GPT-4o-mini стоит **\$0.15 / 1M input**, **\$0.60 / 1M output**. Для внутренних нужд компании (сотни запросов в день) затраты составят **\$20–50/мес**. | Оплата за токены. Доступные цены в РФ, но валютные расчеты и договоры для юрлица в ЕС затруднены. |
| **Сложность развертывания и MLOps** | **Высокая:** настройка Docker, драйверов NVIDIA CUDA, vLLM/Ollama, оркестрация в EKS, мониторинг VRAM и автоскейлинг нод. | **Минимальная (Zero MLOps):** подключение через REST API или LangChain (`ChatOpenAI`) за считанные минуты. Инфраструктура полностью обслуживается провайдером. | **Низкая:** интеграция через Python SDK / IAM токены, требует отдельного аккаунта в облаке Yandex Cloud. |
| **Безопасность (GDPR, SOC 2)** | **100% изоляция:** данные не покидают VPC в AWS EKS. Нулевые риски утечки SCADA-конфиденциальных данных. | В публичном API возможны риски. Для соответствия SOC 2 требуется **Azure OpenAI в ЕС (регионы Frankfurt / Sweden Central)** с включенным *Zero Data Retention*. | Серверы в юрисдикции РФ, что противоречит требованиям регуляторов ЕС и договорам со скандинавскими энергетическими заказчиками. |

### Выводы по выбору LLM:
1. **Для целевого продакшна QuantumForge Software:** Рекомендуется **Azure OpenAI Service (EU: Sweden Central / West Europe)**. Это обеспечивает эталонное качество GPT-4o-mini при строгом соблюдении GDPR и наличии сертификата SOC 2 Type II с гарантией необучения модели на данных клиента.
2. **Для локальной разработки и учебного проекта:** Используется OpenAI API (GPT-4o-mini) как наиболее функциональное решение с поддержкой Few-Shot и CoT reasoning.

## 3. Сравнительный анализ моделей эмбеддингов

Для семантического поиска в базе знаний сопоставлены открытые локальные энкодеры и облачный сервис OpenAI.

| Критерий | Sentence-Transformers (Локальные: `all-MiniLM-L6-v2`, `bge-base-en-v1.5`) | OpenAI Embeddings (`text-embedding-3-small`, `text-embedding-3-large`) |
| :--- | :--- | :--- |
| **Скорость создания индекса** | **Высокая на CPU** (200–400 чанков/сек); на GPU — свыше 2500 чанков/сек. База из 18 000 документов индексируется локально за 10–15 минут без оглядки на сеть. | Ограничена сетевой задержкой HTTP-запросов и лимитами API (Rate Limits). Пакетная индексация занимает 20–35 минут, возможны ошибки `429 Too Many Requests`. |
| **Качество поиска (Retrieval Quality)** | Модели `bge-base-en` и `all-MiniLM-L6-v2` занимают верхние строчки бенчмарка MTEB в категории Retrieval для технического английского языка. Размерность: 384–768 dim. | Очень высокое качество (`text-embedding-3-small` MTEB $\approx$ 62.3%, размерность 1536 dim с возможностью сокращения до 512 dim). |
| **Стоимость владения и использования** | **\$0 за токены.** Модель загружается один раз и работает прямо на процессоре контейнера бота. | \$0.02 за 1M токенов. Первичная индексация обойдется в \$0.50, но регулярная переиндексация 400 страниц/мес влечет постоянные накладные расходы. |
| **Конфиденциальность данных** | **Абсолютная:** сырой текст корпоративной базы знаний не передается третьим сторонам, векторизация происходит в памяти процесса. | Сырой текст передается на серверы OpenAI для векторизации. |

### Выводы по выбору модели эмбеддингов:
Выбираем **локальную модель `all-MiniLM-L6-v2`** (библиотека `sentence-transformers`):
- Полная автономность и конфиденциальность (сырые документы не уходят во внешнюю сеть).
- Высокая скорость работы на стандартном CPU без необходимости в GPU.
- Компактный размер вектора (384 float32), что минимизирует требования к RAM векторной базы.

## 4. Сравнительный анализ векторных баз данных: ChromaDB vs FAISS

Так как база знаний содержит $\approx 21\,000$ документов ($\approx 80\,000 – 100\,000$ чанков при приросте 400 страниц/мес), проведено детальное исследование ChromaDB и FAISS.

| Критерий | ChromaDB | FAISS (Facebook AI Similarity Search) |
| :--- | :--- | :--- |
| **Архитектурный тип** | Векторная база данных (Open Source) со встроенным хранилищем метаданных (SQLite / DuckDB + HNSW). | Высокопроизводительная C++ библиотека для вычисления сходства векторов с Python-биндингами. |
| **Скорость поиска и индексации** | **Хорошая** (HNSW). Для сотен тысяч векторов задержка поиска составляет 10–25 мс. | **Экстремальная.** Оптимизирована под векторные инструкции процессора (AVX2/AVX-512) и GPU. Задержка поиска < 2–5 мс. |
| **Хранение метаданных и текстов** | **Встроенное «из коробки»:** автоматически связывает векторы с исходным текстом документа, идентификаторами и метаданными. | Хранит исключительно числовые векторы и числовые ID. Связка с текстом и метаданными обеспечивается оберткой LangChain (`FAISS.from_documents`). |
| **Сложность развертывания и поддержки** | Простая, но библиотека имеет больше зависимостей. Поддерживает in-memory режим и отдельный клиент-серверный режим. | **Минимальная.** Устанавливается через `pip install faiss-cpu`. Не требует фоновых демонов, серверов и портов. Индекс сохраняется в один локальный файл. |
| **Потребление ресурсов и TCO** | Требует от 1 до 2 ГБ RAM для работы встроенного SQLite/HNSW движка. | **Минимальное:** весь индекс на 100 000 векторов размерности 384 занимает **всего $\approx 150$ МБ RAM**. |
| **Интеграция с Docker** | Требует внимания к зависимостям и совместимости SQLite в Linux-образах. | Идеальная интеграция: легковесный образ Python, стабильная работа без внешних сервисов. |

### Обоснование выбора векторной базы данных:
Для разрабатываемого решения выбрана **FAISS (с интеграцией через LangChain Community)** по следующим причинам:
1. **Эффективность по памяти и скорости:** Для объёма базы QuantumForge Software (до 100 000 чанков) индекс FAISS полностью помещается в RAM приложения (150–250 МБ) и гарантирует время отклика в считанные миллисекунды.
2. **Простота архитектуры (KISS):** Нет необходимости администрировать отдельный контейнер базы данных или следить за целостностью SQLite-файлов. Индекс сериализуется в бинарный файл `index.faiss` и загружается при старте бота.
3. **Безотказность в Docker:** `faiss-cpu` не требует компиляции C++ библиотек при сборке контейнера, обеспечивая максимальную воспроизводимость решения.

## 5. Рекомендуемая конфигурация серверов

### 5.1. Для стенда разработки и текущей проектной работы (Local / Docker)
- **CPU:** 4 ядра (Intel Core i5/i7 или AMD Ryzen).
- **RAM:** 8–16 GB.
- **GPU:** Не требуется (эмбеддинги считаются на CPU, генерация выполняется через API).
- **Диск:** 20 GB свободного места на SSD.

### 5.2. Для целевого продакшн-контура в AWS (QuantumForge EKS)
- **Целевая роль:** Worker Node под поды бота в EKS-кластере.
- **Тип инстанса AWS EC2:** `c6i.xlarge` (Compute Optimized) или `t3.xlarge`.
- **CPU:** 4 vCPU.
- **RAM:** 16 GB RAM (с тройным запасом под рост индекса FAISS, кэш запросов и параллельные воркеры FastAPI/Uvicorn).
- **GPU:** Не требуется при использовании корпоративного шлюза к Azure OpenAI EU.
- **Диск:** 50–100 GB gp3 SSD.
- **Ориентировочная стоимость инфраструктуры:** $\approx \$120–150/\text{мес}$ за вычислительные ресурсы в AWS EKS.

## 6. Итоговые архитектурные варианты

### Вариант 1: Полностью автономный On-Premise (Внутри AWS VPC)
- **LLM:** Локальная Llama-3.1-8B-Instruct (развернута через vLLM на инстансе AWS `g5.xlarge` с 1x NVIDIA A10G 24GB VRAM).
- **Эмбеддинги:** `bge-base-en-v1.5` локально на GPU/CPU.
- **Векторное хранилище:** FAISS в памяти сервиса.
- **Плюсы:** 100% данных изолированы в приватной подсети AWS. Полная гарантия ненарушения коммерческой тайны клиентов ABB и Wärtsilä.
- **Минусы:** Высокий TCO ($\approx \$700–900/\text{мес}$ за GPU-инстанс), необходимость MLOps-экспертизы по мониторингу инференса.

### Вариант 2: Гибридный Enterprise (РЕКОМЕНДУЕМЫЙ ДЛЯ ПРОДАКШНА)
- **LLM:** Azure OpenAI Service (регион EU: Sweden Central) с включенным договором *Zero Data Retention* и сертификатом SOC 2 Type II.
- **Эмбеддинги:** Локальные `all-MiniLM-L6-v2` внутри пода в EKS (нулевая передача сырой документации наружу).
- **Векторное хранилище:** FAISS (in-memory в Docker-контейнере бота).
- **Плюсы:**
  - База знаний и векторизация остаются на 100% внутри периметра компании;
  - Наружу отправляются только минимально достаточные фрагменты найденного контекста по зашифрованному каналу;
  - Превосходное качество следования инструкциям CoT и Few-shot;
  - Низкий TCO ($\approx \$50–80/\text{мес}$ за API + стандартный CPU-инстанс).
- **Минусы:** Зависимость от SLA внешнего корпоративного API.

### Вариант 3: Полностью публичное облако (SaaS / Serverless)
- **LLM:** OpenAI GPT-4o-mini.
- **Эмбеддинги:** OpenAI `text-embedding-3-small`.
- **Векторное хранилище:** Pinecone Serverless / Qdrant Cloud.
- **Плюсы:** Быстрый старт без поддержки серверов.
- **Минусы:** Категорически не подходит для финско-эстонской компании: передача закрытых архитектурных спецификаций SCADA и персональных данных сторонним сервисам нарушает NDA с клиентами.

### Вариант 4: Контейнеризированный прототип (РЕАЛИЗАЦИЯ В ПРОЕКТНОЙ РАБОТЕ)
- **LLM:** OpenAI API (GPT-4o-mini) с техниками Few-Shot и Chain-of-Thought.
- **Эмбеддинги:** Локальный энкодер `all-MiniLM-L6-v2` (`sentence-transformers`).
- **Векторная база данных:** FAISS (`faiss-cpu`).
- **Контейнеризация:** Docker + Docker Compose.
- **Плюсы:** Идеальная воспроизводимость, разворачивается одной командой на любой ОС, быстрое время отклика, полное соответствие учебному заданию.

## 7. Заключение

На основе проведенного анализа для проектной работы утвержден следующий технологический стек:
